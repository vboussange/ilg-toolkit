# ILG Toolkit builds on JAXScape's classes instead of wrapping them

The effective-resistance layer takes JAXScape's and Lineax's objects as they are. A conductance model carries in `solver` a Lineax solver that `ResistanceDistance(solver=...)` accepts, with that solver's own settings, in place of a configuration class that named solvers by string and rebuilt them. `solver=None` selects the default solver of JAXScape's `ResistanceDistance`, so ILG Toolkit names no JAXScape solver class in its code. Each raster shape keeps a JAXScape `GridTopology` and the solver state that `ResistanceDistance.init` prepares and `reinit` refreshes. Every solver has a solver state, which ILG Toolkit carries without checking the type of the solver: like `lineax.linear_solve`, it passes the state's arrays through compiled control flow and keeps its other leaves. Saved models do not record the solver; the template passed to `load_model` supplies it. ILG Toolkit adds what JAXScape does not hold: the mean conductance of an edge, the checks of conductance surfaces and sampling units, and carrying solver states through training.

A configuration class restated JAXScape's solvers, their settings and their errors. Each JAXScape release then needed a matching change here, as raising JAXScape to 0.0.17 did, and a solver JAXScape adds stayed out of reach until ILG Toolkit named it. With JAXScape's objects, every solver that `ResistanceDistance` accepts works, tests pass a CPU double of cuDSS as the solver itself, and the same code works with JAXScape 0.0.17 and 0.0.18. The dependency, `jaxscape>=0.0.17,<0.1.0`, admits every JAXScape release before 0.1.0: a release that keeps the interfaces of `GridGraph`, `GridTopology` and `ResistanceDistance` needs no change here.
